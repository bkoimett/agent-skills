# Project structure checking

Inspect the project structure against project-scaffolder standards. The following guidelines ensure the project remains consistent with the foundation generated by project-scaffolder.

## Preferred structure

- Single-application projects should avoid unnecessary package boundaries (see `project-scaffolder/references/project-structure.md`).
- Monorepos should isolate independently testable packages and keep shared contracts explicit.
- Do not create directories merely to make the tree look sophisticated.

## What to check

- Source code directories should not contain documentation artifacts that belong in the canonical startup documents.
- Configuration files should be present and consistent with the project's stated stack.
- Test files, when present, should follow the project's established conventions.
- Build artifacts and node_modules/.git/ etc. should be excluded from the inspection scope.

## What to avoid

- Unnecessary restructuring of working application code.
- Creating new directories or moving files unless documentation standards cannot be met otherwise.
- Over-refactoring projects that are already functional and well-structured.

## Evidence

Use actual repository evidence — file listings, git ls-files output, and direct file inspection — rather than inventing hypothetical structure. Reference project-scaffolder-generated documents (AGENTS.md, DESIGN.md, WORKFLOW.md, README.md) as the ground truth for what the project foundation should look like.
